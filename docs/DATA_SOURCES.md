# Источники данных Hockey365

В соответствии с правилами проекта, все источники данных задокументированы, определены способы обновления, лимиты и fallback-стратегии.

---

## 1. NHL (Национальная Хоккейная Лига)

* **Источник:** Официальный открытый публичный Web API НХЛ: `https://api-web.nhle.com/v1`
* **Эндпоинты:**
  * Расписание матчей: `/v1/schedule/{date}` и `/v1/schedule/now`
  * Таблицы: `/v1/standings/now` и `/v1/standings/{date}`
  * Детали матча (boxscore & play-by-play): `/v1/gamecenter/{gameId}/boxscore`, `/v1/gamecenter/{gameId}/play-by-play`
  * Составы команд: `/v1/roster/{teamAbbr}/current`
  * Статистика игроков: `/v1/player/{playerId}/landing`
* **Ключ API:** Не требуется.
* **Лимиты и SLA:** Не документированы официально, но открыты для веб-клиентов НХЛ. В адаптере используется User-Agent и таймауты.
* **CORS:** Напрямую из браузера доступ к некоторым эндпоинтам может блокироваться CORS политиками, поэтому данные собираются и нормализуются через Python в репозиторий GitHub Actions (`data/`).
* **Адаптер:** `tools/adapters/nhl_web.py`.

## 2. КХЛ (Континентальная Хоккейная Лига)

* **Источник расписания и счёта:** публичный мобильный backend КХЛ `https://khl.api.webcaster.pro/api/khl_mobile` (в API заявлен как официальный; отдельная лицензия и Terms для перераспределения в репозитории не подтверждены).
* **Эндпоинты:** `data.json` (включая `current_stage_id` и `stages_v2`), `events_v2.json` (события матчей) и `teams_v2.json` (справочник команд). Браузерный клиент — `assets/js/core/khl-feed.js`; отдельный Python-адаптер публикует fallback-срез. Запросы без `Origin` отвечали с CORS `*`, но запрос с браузерным `Origin` может получать 403: CORS-заголовок сам по себе не доказывает доступность в браузере.
* **Адаптер:** `tools/adapters/khl_aggregator.py`. Он запрашивает rolling-окно «вчера — следующие 7 дней» с параметрами `stage_id`, `q[start_at_gt_time_from_unixtime]`, `q[start_at_lt_time_from_unixtime]`, `order_direction=asc` и постраничным `page` до пустой страницы (с лимитом). Для даты матча приоритетен `start_at`; `event_start_at` используется только как fallback. Ответы и полная `match` schema проверяются до записи, placeholder `0:0` будущей игры не становится счётом, матчи группируются по UTC-дате и получают provenance-поля `source`.
* **Политика публикации:** `KHL` намеренно остаётся в `data/meta.json.unverifiedCompetitions` даже после успешной проверки матчей: этот глобальный блок защищает старые standings, players и team dossiers. Новые записи получают `source.provider=KHL mobile backend`, `source.verified=true` и `source.verifiedMatches=true`; только они отражаются в очищенных date feeds. `data/meta.json.sourceStatus.KHL` получает `verified=true` и `verifiedMatches=true` для успешного match feed. При HTTP/JSON/schema ошибке legacy KHL снова скрывается, старые match-файлы не перезаписываются, а fictitious/fallback данные не создаются.
* **Правовые ограничения:** публичность endpoint и CORS не подтверждают право на републикацию. Адаптер не публикует ссылки на m3u8/iframe и не заявляет наличие лицензии; условия использования необходимо проверить до коммерческого или широкого распространения.
* **Детали матча:** `match_id` и мобильный `event.id` — разные идентификаторы. Проверенный `eventId` передаётся в ссылке только как подсказка; ответ `events_v2.json?q[id_eq]=…` сверяется по обоим ID, stage и типу. `q[match_id_eq]` в проверке игнорировался источником и не используется. Без подсказки и snapshot доступен лишь короткий поиск: отсутствие подтверждённого совпадения показывается как недоступность, а не чужой матч.
* **Доступные поля:** счёт, статус, периоды (когда опубликованы), дата и команды. Публичный feed не подключает точный таймер, события игроков, составы или статистику КХЛ: эти блоки остаются пустыми/помеченными недоступными.

## 3. Трансляции и права на просмотр

* **НХЛ:** расписание API содержит официальную ссылку NHL Gamecenter (`gameCenterLink`). Она публикуется как внешняя ссылка на матч-центр, а не как обещание бесплатного видео: доступ к просмотру зависит от региона, подписки и текущих прав вещателя.
* **Встроенные плееры:** допускаются только вручную подтверждённые HTTPS embed-ссылки из разрешённого списка. Плеер не создаётся до явного клика пользователя; неподтверждённые, HTTP-, `javascript:`- и произвольные iframe-ссылки отбрасываются.
* **КХЛ и другие лиги:** если проверенной ссылки правообладателя нет, интерфейс показывает честное состояние «трансляция недоступна», без подмены ссылкой на агрегатор или пиратский источник.

## 4. Доставка live-данных без Node

* Статический frontend сначала использует официальный NHL Web API, если браузерный CORS разрешён.
* Для обычного shared hosting доступен `api/nhl.php` — фиксированный PHP cURL bridge без Node, базы и ключей. Он используется только для официальных `schedule`, `gamecenter` и `player` endpoints.
* `api/khl.php` — аналогичный необязательный мост КХЛ (PHP 8.1+, cURL). Только `data.json`, `events_v2.json`, `teams_v2.json` и ограниченный набор числовых фильтров; фиксированный upstream, SSL-проверка и запрет редиректов. Ответ очищается от видео, iframe, IP и telemetry до передачи frontend.
* Если хостинг не исполняет PHP/edge functions, frontend использует последний Python-собранный snapshot. Это не realtime: частота определяется `.github/workflows/data-update.yml`, а UI показывает время и режим источника.

## 5. Медиа-активы и логотипы

* **Логотипы клубов и лиг:**
  * Хранятся локально в формате SVG в каталогах:
    * `/assets/logos/comp/` — эмблемы лиг (KHL, NHL)
    * `/assets/logos/teams/` — векторные логотипы клубов
    * `/assets/flags/` — флаги стран проведения (RUS, USA, CAN, BLR, KAZ, CHN)
  * В событиях НХЛ разрешены только headshot URL, возвращённые официальным player API с хоста `assets.nhle.com`; при ошибке — нейтральный силуэт. URL не строится по произвольному ID.
  * Эмблемы КХЛ могут приходить из проверенного feed с HTTPS-хоста `thumbs.webcaster.pro`; локальные эмблемы служат fallback.
  * Для каждого клуба предусмотрен fallback SVG-плейсхолдер с клубными цветами и аббревиатурой.

## 6. Бюджет запросов и кэширование

1. Скрипты идемпотентны.
2. При сбое сетевого запроса старые JSON-файлы в `data/` не затираются (пишется во временный файл -> валидация схемы -> атомарная перезапись).
3. Главная, live-центр и активная страница матча опрашивают источники каждые 10 секунд; события не кэшируются Service Worker. Это частота запросов, не SLA upstream. При недоступности источника используется подтверждённый snapshot с собственным временем получения.
4. Lookup фото игроков НХЛ ограничен четырьмя параллельными запросами, bounded очередью и кешем. Повторные участники событий не создают отдельный запрос при каждой перерисовке.

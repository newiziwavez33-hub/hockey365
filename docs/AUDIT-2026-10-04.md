## Достоверность данных — блокирующий вопрос

- NHL-адаптер использует официальный NHL Web API; больше не сочиняет периоды, события, составы и статистику. Дата среза обновляется после обязательных операций получения данных.
- Прежний генератор КХЛ выпускал неподтверждённые матчи, таблицы, плей-офф, новости и профили. Генерация отключена; `data/meta.json` помечает KHL как `unverifiedCompetitions`, а клиент не показывает эти результаты в матчах, таблицах, поиске и профилях. Неатрибутированные новости (без внешней ссылки на источник) также не показываются.
- **Остаточный риск:** старые JSON КХЛ и тексты новостей всё ещё физически лежат в `data/`, доступны по прямым URL и могут присутствовать на уже опубликованной версии. Перед заявлением «полностью достоверная КХЛ» нужен проверенный поставщик и отдельная очистка/миграция этих файлов, индекса и sitemap. `SPORTS_API_KEY` сам по себе не подключает поставщика. Не выдавать опубликованный старый сайт за уже обновлённый.
- GitHub Pages обновится только после публикации этих изменений. Проверка HTTP 200 сама по себе не подтверждает достоверность или работоспособность JS.

## Продолжение: иконка, события и КХЛ (05.10.2026, МСК)

Предыдущие разделы — исторический аудит, не текущий статус подключения.

### Реализовано

- Все 15 опубликованных HTML используют общий favicon `assets/icons/hockey365.svg` и версию локальных ресурсов `1.8.2`. SVG воспроизводит Material Symbols `sports_hockey` и оформление шапки из сохранённого `docs/stitch_design.html`, а не эмблему КХЛ. Живой проект Stitch через MCP **не прочитан**: подключение отсутствует в доступных действиях.
- В обзоре событий матча показываются имена, официальные NHL headshots и имена авторов передач. Технические ID скрыты; неизвестный участник получает нейтральный силуэт и подпись. Четыре параллельных lookup, bounded очередь/кеш, защита от устаревших async-обновлений и ошибочных фото.
- Бесплатный без ключа мобильный API КХЛ подключён для счёта, статуса, календаря и эмблем. Клиент: `assets/js/core/khl-feed.js`; необязательный безопасный PHP-мост: `api/khl.php`; snapshot-сборщик: `tools/adapters/khl_aggregator.py`.
- Протокол live-матча открывается без опубликованного JSON: `buildMatchLink` передаёт `eventId` как подсказку, независимо проверяемую по фактическому `match_id`, stage и типу. Холодная ссылка без подсказки/snapshot имеет ограниченный поиск; чужой матч не подставляется.
- НХЛ и КХЛ обновляются независимо. Ошибка одной лиги не скрывает другую. API и сохранённый срез различаются в UI; snapshot не обозначается как realtime.
- После живой загрузки опубликован 33-матчевый rolling-срез КХЛ; за 04.10.2026: Нефтехимик — Сибирь 3:2, Автомобилист — Амур 0:3, Спартак — Барыс 3:4 (Б). Это результаты полученного среза, не обещание текущего live-счёта. Статусы/ID/счёт/schema и хоккейные ограничения проверяются до записи. Перенос матча не оставляет старый дубль даты.
- Глобальный блок старых KHL standings/players сохранён. Таймер, события игроков, составы и расширенная статистика КХЛ этим feed не подключены. Медиа-URL/IP/telemetry в публикуемые данные и PHP-ответы не переносятся.

### Ограничения и публикация

- Публичность мобильного API/CORS `*` не подтверждает лицензию на републикацию. `licenseConfirmed: false`; видеотрансляции КХЛ не подключены. До публичного/коммерческого распространения требуется проверка условий или разрешение правообладателя.
- Запрос с браузерным `Origin` может получать 403. На PHP-хостинге проверен мост; полностью статический хостинг не гарантирует live и при блокировке использует срез GitHub Actions. Опрос 10 секунд — частота клиента, не SLA upstream.
- Старые legacy JSON физически остаются в `data/`; UI их не показывает, но отдельная очистка публикации/поиска/sitemap ещё нужна до заявления о полной достоверности всего набора.
- Этот этап не закоммичен и не отправлен. Изменения на опубликованном GitHub Pages не проверены и не заявляются опубликованными.
- Для чтения актуального проекта Stitch нужен workspace MCP в OmniRush.ai: Settings → Library → Advanced settings → Add workspace MCP, затем проверка agent access. Секреты не сохранять в проекте и не передавать в чат.
